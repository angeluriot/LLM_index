  Choix de structure (à valider)

  - Clés de version : la date du snapshot API ("2024-05-13"), ou à défaut la
    date de sortie. Je l'utilise aussi pour les modèles à une seule version,
    pour ne pas avoir à renommer la clé si une deuxième version sort.
  - Modèles multi-versions : GPT-4o (5 versions, dont les chatgpt-4o de janvier
    et mars 2025), GPT-4, GPT-4 Turbo, GPT-3.5 Turbo (ChatGPT de nov. 2022, puis
    0301, 0613, 1106 et 0125), GPT-4o Realtime et GPT-5.5 Instant (mai et
    juin 2026).
  - Noms génériques : pour les modèles multi-versions, les noms comme GPT-4o ou
    gpt-4o ne figurent dans aucune version. Un résultat qui les cite tombera
    donc sur version: null.
  - Efforts : j'ai repris les valeurs de la doc API
    (None/Minimal/Low/Medium/High/Xhigh/Max), et [""] pour les modèles sans
    raisonnement configurable. o1-mini et o1-preview sont en [""] parce que leur
    API n'accepte pas reasoning_effort, alors qu'Epoch leur attribue des
    résultats low/medium/high.
  - access: null pour les modèles réservés à des programmes d'accès restreint
    (GPT-5.4/5.5/5.6 Cyber, GPT-Rosalind, GPT-6 Rosalind, GPT-6 Astra Law),
    puisqu'ils ne sont pas largement disponibles. Si tu préfères la date de
    sortie, c'est rapide à changer.
  - Prix : j'ai pris les tarifs API actuels d'OpenAI. Pour gpt-oss, qui n'a pas
    d'API OpenAI, j'ai pris la médiane d'Artificial Analysis. Les modèles
    uniquement disponibles dans ChatGPT (GPT-5.6 Sol Pro, GPT-6 Astra Pro,
    Codex-Spark, codex-1) ont null.
